# 0005. 每個專案一個 qa_context 資料夾，丟進去的檔案自動參照；圖片只在問到圖時才送

## Status

Accepted（2026-10-24）。取代 ADR 0003 裡「用 TALK_CONFIG 指向 talk.toml」的做法；資料仍然放在 repo 外，這一點不變。

## Context

原本每場演講要寫一份 talk.toml，逐一列出論文、筆記、投影片的路徑，而且只支援一篇論文、不支援圖片。講者希望：換一個專案時，只要把資料丟進固定的資料夾就能用；論文的圖、表、截圖也要能參考。

2026-10-24 用 SurgiFlowVid 這場的資料實測（Sonnet 5.5、快取已預熱）：只用文字時 context 8.8 萬 tokens，第一個字 2.0–3.9 秒、完整回答 5.5–7.6 秒；加上 29 張圖表後 context 12 萬 tokens，第一個字 7.8–10.1 秒、完整回答 10.9–14.0 秒。就算問題和圖無關，也一樣變慢。

## Decision

- 每個專案放一個 `qa_context/`，用 `QA_CONTEXT` 指定。裡面的檔案依副檔名分類：`*.pdf` 和 `*.paper.txt` 是論文，`*.md`、`*.txt` 是筆記，`*.png`、`*.jpg`、`*.jpeg`、`*.webp`、`*.gif` 是圖片，`*.tsx` 是 open-slide 投影片。子資料夾也會讀，`sessions/` 和隱藏檔除外。`talk.toml` 變成選配，只放題目、講者、場合、詞彙。
- `qa.py init <專案>` 建立這個資料夾、範本 talk.toml、`.gitignore`（排除 sessions/），以及雙擊啟動檔。
- 執行中每 10 秒檢查資料夾有沒有變動。有變動就重建 context、重新預熱，並通知頁面。
- 論文可以有好幾篇。每篇各自是一份 content document，引用會標出是哪一篇的第幾頁。
- 圖片縮到長邊 1568 px，放在第二個快取點後面。只有新逐字稿提到圖（「圖」「Fig」「畫面」「看起來」等）時才送；表格的數字在文字版裡就有，不需要送圖。兩段前綴都會預熱。

## Consequences

- 好處：換專案只要跑一次 init、把檔案放進去。執行中加檔案也不用重開。
- 好處：一般問題維持只用文字的速度。問到圖時，模型看得到圖：Fig. 5 的失敗案例，它能講出「器械種類對了、位置偏移」。
- 代價：要不要送圖是用關鍵字判斷的，問法沒提到這些字（例如「那個生成失敗的例子」），就不會送圖。
- 代價：問到圖的題目，答案會慢 5–6 秒。
- 代價：每次 reload 都會重寫快取，資料夾常常變動的話，費用和第一次回答的延遲會增加。
- 代價：Path.rglob 不會進入以 symlink 連結的資料夾，圖片要個別建 symlink，或直接複製進來。
