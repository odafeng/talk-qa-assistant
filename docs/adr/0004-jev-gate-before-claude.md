# 0004. 先讓 Jev 判斷要不要回答，有把握才照它的判斷

## Status

Accepted（2026-10-23）

## Context

每一行聽眾發言都要判斷三件事之一：有新問題要回答、問題還沒講完、不需要回答。原本這個判斷和寫口語稿是同一次 Claude 呼叫。第一場實際 Q&A（2026-10-23）的 35 次判斷裡，有 18 次結果是略過或等待：每次都要等 Claude 約 2 秒、付一次讀快取的費用，而且排在真正的問題前面。

TypeSafe Jev 只做結構化的判斷、不產生文字。拿那場的真實逐字稿重播，53 行聽眾發言每一行都同時問 Claude 和 Jev：

- Jev 每次約 0.2 秒，53 次總共 $0.006；Claude 中位數 1.96 秒，最慢 7.2 秒，總共約 $1。
- 整體一致 79%。不一致的 11 個裡，9 個是 Jev 錯：它把自我介紹和主持人預告判成「還沒講完」，或用很低的信心把同一題的後半段判成新問題。
- 信心 ≥ 0.8 的判斷有 31 個，和 Claude 一致 30 個。唯一不一致的是「整台手術四小時，負擔會不會太大」：Claude 漏答，Jev 是對的。

## Decision

- 每次自動判斷先問 Jev（`jev-1.13.0`，固定版本），選項是 `new_question`、`unfinished`、`no_answer`。
- 信心 ≥ 0.8：「不需要回答」和「還沒講完」直接照 Jev，不呼叫 Claude。「有新問題」則請 Claude 直接寫口語稿，不再自己判斷。
- 信心 < 0.8、Jev 沒有回應，或是強制的請求（手動輸入、「現在回答」、等待逾時）：照舊交給 Claude 判斷。
- `TYPESAFE_API_KEY` 是選配。沒有這把 key 時，完全回到只用 Claude 的做法。
- 同時放寬 Claude 的同題規則：主題相近但問的是不同面向，要當成新問題。

## Consequences

- 好處：重播時 Claude 的呼叫從約 59 次降到 35 次，23 行只靠 Jev 在 0.2 秒內處理完；10 個真正的問題全部有回答，包括原本漏答的那題。
- 好處：判斷有信心值，也記在問答紀錄裡（`by`、`jev` 欄位），之後可以拿來調門檻。
- 代價：每個真正的問題多花約 0.2 秒（先等 Jev）。
- 代價：多一家服務、一把 key，要維護固定的模型版本。
- 代價：0.8 的門檻只用一場、53 行的資料定出來，沒有人工標記的標準答案；不一致的部分是用 Claude 和人工判讀比對的。
- 代價：放寬同題規則之後，偶爾會把同一題的後半段再答一次（重播時 11 次回答裡有 1 次）。
